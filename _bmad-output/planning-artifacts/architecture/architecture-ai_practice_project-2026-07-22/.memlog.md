- (constraint) INHERITED INVARIANTS (PRD §8, binding, read-only): no black-box recommendations; precedent-backed-or-not-claimed; coach-is-boss; no unprompted FOMO/push alerts; capture-not-beat; pull-not-push; anxiety-reducing-by-design.
- (constraint) v1 scope = COACH-ONLY; guru deferred but architecture must leave a clean coach/guru boundary + broker-adapter seam for future extension without touching coach logic.
- (constraint) Multi-user with STRICT per-user data isolation; brokerage OAuth tokens handled as high-sensitivity secrets (NFR1/NFR5). Propose-and-approve only — no autonomous trading (FR8).
- (constraint) Trust invariants must be enforced STRUCTURALLY (NFR2): an unbacked/black-box recommendation must be physically un-surfaceable, not just discouraged by prompt. Precedent is data-retrieved, never LLM-originated (FR13). Teaching (FR18) and reasoning (FR12) are ONE engine.
- (constraint) USER REQUEST: React on the UI (binding). Coach LLM targets latest Claude — Sonnet 4.6 default, Opus 4.8 for harder reasoning (per current model availability).
- (decision) STACK — Frontend: Vite 7 + React 19 SPA (presentation ONLY). Backend: FastAPI (Python) owns ALL business logic. Binds: the SPA/backend split IS the NFR2 enforcement boundary. Prevents: the UI ever originating or surfacing a recommendation the backend didn't build and bless.
- (decision) STACK — DB: PostgreSQL 18. Brokerage OAuth tokens encrypted at APP layer (AES/Fernet), key held outside the DB (env/secret-manager). Auth: FastAPI-Users (self-hosted email+password + JWT) — user confirmed via 'yes' to the recommended lean; hosted Supabase Auth was the considered alternative.
- (decision) STACK — Brokerage access behind a broker-adapter interface; v1 impl = schwab-py v1.5 (alexgolec), NOT itsjafer/schwab-api (browser-scraper, rejected). Market data = Tiingo EOD free tier (Stooq backup); yfinance rejected for prod (unofficial/ToS). LLM = Anthropic Python SDK, Claude Sonnet 4.6 default / Opus 4.8 for hard reasoning.
- (version) Verified versions (web, Jun 2026): Vite 7.x, React 19.2, FastAPI 0.136, Postgres 18, FastAPI-Users 13.x, schwab-py 1.5.0 (alexgolec, maintained).
- (decision) COACH ENGINE / NFR2 enforcement: a Recommendation is a validated STRUCTURED OBJECT {action, reasoning, evidence[], uncertainties[]}, assembled server-side via pipeline RETRIEVE(precedent by code) -> COMPOSE(LLM cites only handed evidence) -> VALIDATE(gate: reasoning+>=1 real evidence w/ all cited IDs present+uncertainties) -> SURFACE(only passing objects). Binds: how coach output is produced. Prevents: black-box recs (reasoning required), hallucinated precedent (citations must match retrieved set), missing-uncertainty. LLM uses structured-output/tool-use. Teaching(FR18)=reasoning(FR12) same field, one engine.
- (decision) Two backing types: EVENT-PRECEDENT backing (tactical/contextual claims, from Precedent Engine) vs STRATEGY backing (the default consistency/capture-not-beat recommendation, always-available evidence base). Binds: what counts as valid evidence for the validator. Prevents: omission-bias dead-ends — because the strategy-backed DEFAULT PLAN is always valid, the engine is never empty-handed.
- (decision) No-confident-special-call fallback: coach returns the DEFAULT-PLAN recommendation (make the regular index contribution / stick to plan) PLUS a plain-English reason why there's no special call. 'I won't force a call' applies only to tactical calls; the strategy-backed default is the ever-present floor. Serves anxiety-reduction + defeats omission bias.
- (decision) Co-sign (FR16) = the blessed Recommendation object persisted IMMUTABLY at approval; Replay (FR17) = reading that record back. One artifact powers recommend -> co-sign -> replay. Binds: the shared decision-record shape/owner. Prevents: divergent representations of 'the decision' across features.
- (decision) PRECEDENT ENGINE: deterministic, code-owned service over a LOCAL historical market-data store (Tiingo EOD -> Postgres 'market_daily', daily refresh job). It is the SOLE source of factual market statistics/precedent; the LLM narrates its structured outputs and never computes or recalls them (enforces FR13). Its outputs = precedent records with stable IDs = the evidence[] objects cited in Recommendation (Call #2). Binds: ownership of all factual stats. Prevents: LLM-authored/hallucinated numbers.
- (decision) v1 'similar event' matching = QUANTITATIVE drawdown-based (drop magnitude + velocity from recent peak -> historical windows with comparable drops -> recovery time + forward-return distribution at 3/6/12mo). A scary headline is only the TRIGGER; the backed answer is always keyed to the drawdown, NOT to classifying the event. Event-category tagging deferred (optional later enrichment). Binds: how precedent is matched. Prevents: LLM event-classification drift + subjective curation burden. missed-growth (FR19) also computed here from historical returns on idle cash.
- (decision) PARADIGM: modular monolith, hexagonal at the edges — one deployable FastAPI app; external deps (brokerage/LLM/market-data) behind PORTS with swappable adapters. Modules: React SPA (presentation) -> FastAPI API (auth/sessions) -> Coach Engine -> {Precedent Engine, LLM Gateway, Broker Port}; Market-Data Ingestion; Weekly Digest (opt). Binds: overall structure + dependency direction (inward: UI->API->Coach->ports; Coach depends on interfaces not concretes).
- (decision) OWNERSHIP (anti-divergence): one owner per concern — Coach Engine = sole writer of Recommendation/decision records; LLM Gateway = sole caller of Claude; Precedent Engine = sole source of stats; Broker Port = sole path to brokerage (portfolio truth reconciled from broker, cached read-only elsewhere). ONE execution path: propose -> user-approve -> Coach Engine -> Broker Port -> reconcile -> persist; no other module places orders (FR8/9/22/23). Prevents: clashing writers, phantom orders, divergent portfolio truth.
- (decision) RESERVED SEAMS (design-for-future, don't build in v1): (1) Broker Port — new brokerage = one new adapter, zero coach changes. (2) Coach/Guru seam — future guru is a SUGGESTION SOURCE feeding INTO the same propose->approve->bless pipeline; it can never call execution directly or bypass coach authority (keeps coach-is-boss true once guru exists). Prevents: guru bypassing gates; brokerage lock-in.
- (decision) Reviewer-gate hardening: +AD-12 Evidence Record Contract (fixed evidence shape), +AD-13 Broker Port Contract (normalized OrderOutcome + idempotency key -> no dup orders on timeout, get_order_status reconciliation), +AD-14 portfolio-cache single-writer projection (broker-authoritative, reconcile-wins). Tightened AD-2 (action_label + typed order_intent), AD-3 (Coach Engine owns prompt-assembly + citation check; LLM Gateway = transport + deterministic model routing), AD-5 (schema_version on snapshot), AD-9 (guru injects as SuggestionSource at retrieve/compose), AD-10 (fail-closed scoped-repository layer + explicit SYSTEM scope for jobs).
