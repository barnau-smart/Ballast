## 3. What went well

**1. The atomic-claim primitive finally exists — the Epic 4 #1 blocker is structurally closed.**
6.1 introduced exactly the primitive the Epic 4 retro said was missing: an intermediate `cosigning` state, a `proposed → cosigning` claim as a rowcount-gated conditional `UPDATE`, committed *before* the broker call, backed by a `uq_decision_record_idempotency_key` unique index and a stable per-decision key minted at `/recommend`. Proven with genuine two-`AsyncSession` races against the Postgres test DB — not a sequential proxy. The digest double-send (5.1) was folded into the same pass as one root cause, exactly as planned.

**2. The double-order "fence, not blocklist" catch (6.3) is the epic's most important save.**
Both reviewers found that the post-placement region (`extract order id → status read → map`) sat under a *curated exception blocklist*. Against a real broker, any missed exception type *after* a successful placement escapes the port → `approve` releases the atomic claim → **a second real order** (Schwab honors no client idempotency key). The fix restructured it into a fence: the placement write is the last statement of the typed pre-placement `try`; everything after runs in a second `try` whose `except Exception:` returns `TIMEOUT` with the `order_ref` preserved. This is the difference between "hardened" and "shipped a money bug."

**3. The structural-teeth pattern carried forward and stayed honest about failure classes.**
6.3 keeps three failure classes distinct and refuses to collapse them: transport exception → `TIMEOUT` (indeterminate, never phantom); HTTP error response → truthful `REJECTED`; can't-size → calm `OrderNotPlaceableError` 422 with the claim released. 6.5 applied the same discipline to reads — `fetch_portfolio` *raises* `SchwabReadError` rather than returning an empty snapshot that would reconcile a real user's cache to nothing.

**4. Adversarial review is doing real work.**
Independent second passes on 6.2/6.5/6.7 found no new actionable defects but converged on the *same* highest-ranked residuals the first pass already deferred — evidence the triage is calibrated, not rubber-stamping. NaN/Infinity handling was hunted across multiple stories (6.3 arithmetic leak, 6.4 wire format, 6.7 `_extract_avg_price` `is_finite()` guard) until the non-finite path was closed end-to-end.

**5. Scope discipline held under pressure.** 21 new deferred items were logged with clear reasoning and correct seam hand-offs (6.3→6.7 for durable reconciliation; the atomicity residuals routed to a dedicated pass). High reject counts (7, 9, 24, 5…) with documented rationale. The loop did not scope-creep into go-live territory it wasn't chartered for.

## 4. What was hard — the systemic findings

**⭐ FINDING #1 — Atomicity is *still* the recurring blind spot. It got closed at the approve seam and immediately reappeared at every new seam Epic 6 introduced.**
Epic 4 flagged concurrency as the #1 gap. 6.1 closed it at `approve` + digest. But the *same class* re-emerged at each new seam this epic built:
- **6.5** — the two-table `portfolio_cache` + `portfolio_balance` reconcile is a lock-free read-modify-write (TOCTOU). The new `uq_portfolio_balance_owner` index is only a partial mitigation.
- **6.7** — the reconcile endpoint has no atomic claim/row-lock; two concurrent reconciles double-read the broker and last-writer-wins the snapshot (read-only — no double-place, but still a race).
- **6.3** — a post-placement `cosign`+`commit` failure strands the record in `cosigning` with a *live order* and *no persisted `broker_ref`* — unrecoverable even by 6.7, which keys on `broker_ref`.

The primitive from 6.1 exists but wasn't generalized into a reusable claim helper, so each new seam re-litigates atomicity from scratch. **This is the pattern to break: introduce one reusable atomic-claim/row-lock primitive and apply it at every mutating seam, rather than closing them one funeral at a time.**

**⭐ FINDING #2 — There is no production database migration path, and Epic 6 quietly made this a hard go-live blocker.**
Every schema change this epic relies on assumes `create_all` — which *never ALTERs an existing table*. Epic 6 added, across stories, at minimum: `uq_decision_record_idempotency_key` (6.1), `broker_ref` column (6.3), `portfolio_balance` table + `uq_portfolio_balance_owner` (6.5), `(owner_id, co_signed_at)` composite index (6.6), and `reconciliation_snapshot` + `reconciled_at` columns (6.7). On a provisioned production DB, **none of these exist**, and several are load-bearing for correctness (the unique index *is* the double-place backstop). This was logged as a "go-live schema step" in five separate stories but there is still no Alembic (or equivalent) migration story. It cannot be hand-waved.

**⭐ FINDING #3 — "Go Live" went nowhere live. Same cliff as Epic 4 Finding #2, one epic later.**
The epic is titled *Go Live*, but not one real paid Anthropic call and not one real Schwab order has been made. The real adapters are wired and *very* well hardened, but every "done" story's live behavior is asserted against fakes + documented-shape fixtures. Concretely: **21 of the 40 open deferred-work items sit on this credential-gated, unexercised path** — Schwab order-JSON field names ("re-confirmed at go-live"), the token-envelope round-trip, the `fetch_portfolio` sync-blocking-in-async stall, and the config/auth-fault→`TIMEOUT` retry dead-ends. These are *theoretical until exercised* — which is exactly the risk: they'll be discovered live, with real money, unless a deliberate go-live spike surfaces them first.

**Smaller frictions:**
- **`uv.lock` anthropic-drift is finally retired** — 6.2 legitimately pins + commits `anthropic`; the revert-toil from Epics 4–5 is over (matches the `uvlock-anthropic-drift` memory).
- **Partial-fill terminality is an unmade product decision** (6.7): `partial` is classified terminal, so a partial fill that later completes to `filled` can never be re-reconciled. Genuine product call, not a bug.

## 8. Key takeaways

1. **The atomic-claim primitive works — now make it reusable.** 6.1 proved the pattern; 6.3/6.5/6.7 proved that *not* generalizing it means re-fighting atomicity at every new seam. One helper, applied everywhere, ends the whack-a-mole.
2. **"Done against fakes" is *still* not production-readiness — two epics running.** Epic 4 Finding #2 and Epic 6 Finding #3 are the same cliff. The live exercise is now the single highest-leverage unstarted thing in the project.
3. **A schema without a migration path is a latent outage.** Five stories each said "go-live schema step" and moved on; that debt has now compounded into a real blocker that must be a first-class story, not a footnote.
4. **The review layer is earning its cost.** The double-order fence (6.3) alone justified the adversarial passes — that was a real second-real-order bug caught before any money moved.
