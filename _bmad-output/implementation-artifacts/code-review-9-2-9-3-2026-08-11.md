## Decision-needed

- [x] **[9-3][Decision] SELL guardrail bypass via unvalidated `parked_symbols` + verbatim `/approve` intent.** The SELL scope gate admits any symbol in the user's `parked_symbols` (`coach/execution.py:319`); `set_config` does NOT validate that a parked symbol is held or is a money-market fund (`cash/config.py`); and `/approve` builds the `OrderIntent` verbatim from `body.order_intent` (`api/coach.py:697`) — the co-signed decision snapshot bounds neither symbol nor amount. Net reachable surface: a user can co-sign an **arbitrary-amount SELL of any security they hold** by tagging it "parked," defeating the index-core SELL guardrail; and the immutable decision-record audit snapshot won't match what was placed. **Bounded** to the user's OWN account/holdings (per-user isolation holds; broker rejects short-sells/over-holdings) and **9-3 is not yet real-money** (`BROKER_ADAPTER=fake`). Options: (a) harden now — bind `order_intent` to the co-signed decision snapshot, and/or validate `parked_symbols` to held money-market funds + re-check in the SELL gate; (b) accept as a tracked HARD-GATE to close before enabling real-money liquidation; (c) accept as-is. Rec: (b) now, (a) before real money.

## Patch

- [x] **[9-2][High] Frontend glyph/label re-introduces the "market fell" lie the backend patched.** `MissedGrowthMeter.jsx:165` derives the ▲/▼ from `directionAndMagnitude(forgone_growth)` and `missedGrowth.js:57` labels `forgone_growth < 0` as "loss avoided". When the market ROSE (`window_return > 0`) but parked yield outpaced it (`forgone_growth < 0`), the meter shows ▼ + "loss avoided" directly beneath an honest "the market rose, you came out ahead" sentence. Fix: key the loss-vs-ahead framing (and the down/loss glyph) on `window_return`, not the forgone-growth sign; add a rising-market-parked-outperformed fixture. [ballast/frontend/src/lib/missedGrowth.js:54-58, ballast/frontend/src/components/MissedGrowthMeter.jsx:163-197]
- [x] **[9-3][Med] Planner can propose selling the fund you're buying.** `normalized_buy_symbol` (`liquidation.py:304`) is computed but never passed to `_largest_parked_holding` (`:351`), so a buy target the user also tagged parked can be selected as the sell. Fix: exclude the normalized buy symbol from candidates. [ballast/backend/cash/liquidation.py:304,351]
- [x] **[9-3][Med] Non-atomic resume/cancel state transition.** `resume_pending_buy` / `cancel` do `repo.get` → check `status=='awaiting_funds'` → mutate → commit with no row-lock/conditional update. Concurrent double-resume mints TWO co-signable BUY decisions for one pending intent; a resume+cancel race leaves a `cancelled` row with a live minted BUY. Fix: conditional `UPDATE ... WHERE status='awaiting_funds'` (mirror `decision_record.claim_for_cosign`). [ballast/backend/api/cash.py:572-607,619-646]
- [x] **[9-3][Low] Write-on-render double-submit.** The `/liquidation-plan` POST (durably inserts a PendingBuy + proposed SELL) fires from a `useEffect` with no one-shot `useRef` guard (unlike `PendingBuyCard.jsx:26`). Add the ref guard. [ballast/frontend/src/components/CoachConsult.jsx:141-176]
- [x] **[9-2][Low] Reserve line can claim to protect more than exists.** In `fully_reserved` with reserve > cash+parked (e.g. cash 1000, reserve 5000), the line reads "$5,000.00 stayed protected." Cap the displayed protected amount at actual cash+parked (or reword). [ballast/frontend/src/lib/missedGrowth.js:68-73]
- [x] **[9-3][Low] Missing `cash_states` dead-ends the buy flow.** `readyToTrade = Number(portfolio?.cash_states?.ready_to_trade)` → `NaN` on a degraded payload → early return → no LiquidationCard → hard `/approve` failure (the exact dead-end 9-3 removes).
