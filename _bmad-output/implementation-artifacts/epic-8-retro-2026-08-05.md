## What went well

- **The north-star shipped, safely.** The full "buy near the low & wait, then cancel" capability plus the AI suggest button exist end-to-end, with the core safety invariant intact throughout: **the backend computes every number deterministically; the LLM only narrates; a human always executes** via the unchanged propose→approve→co-sign path.
- **8.1–8.4 flowed cleanly** through the autonomous bmad-loop. Once we committed to strict-bmad (`/bmad-create-story` → `bmad-loop run`), story creation and dev/review were smooth.
- **Independent verification earned its keep** — running the tests ourselves (un-batched, timed) caught real defects the loop's self-report hid, twice.
- **Test suite transformed** — from a 13+ min tax that made healthy loops look "stuck" to ~40s and 100% green (and no longer coupled to a developer's local `.env`).

## What was hard (lessons)

1. **The autonomous loop cannot self-verify test-performance / async / env-sensitive work.** It marked Story 8.5 `done` **twice** on false "108 passed 3× / ~15s" self-reports that were actually (a) an infinite hang, then (b) a 13m45s run. Its in-run execution masked both the hang and the real-API latency.
   - *Lesson:* for that class of story, require an **independent, un-batched, timed** run before `done`. (Saved to memory: `loop-cannot-self-verify-test-perf`.)
2. **The demo `.env` leaked into the test suite.** `LLM_ADAPTER=anthropic` + a real key meant tests hit the **live Anthropic API** (~10s/test → the ~13 min; also non-deterministic → flaky), and the "fake-by-default" factory tests failed because `.env` supplied real adapters `monkeypatch.delenv` couldn't clear.
   - *Lesson:* **test suites must be isolated from a developer's local `.env`** (use code defaults). Fixed in `tests/conftest.py`.
3. **8.6's loop wedged in `dev-verify`** — an "attempt stopped with committed work + auto-rollback OFF" recovery pause that `resume` would not auto-clear. The loop's recovery model assumes *discard-and-redo*; but the committed work was verified good.
   - *Lesson:* when committed work is independently verified good, **review-and-accept** (here: `bmad-code-review` on the diff) beats discarding and re-running.
4. **Docker Postgres crashed repeatedly** (`Exited (255)`) under the repeated full-suite runs, masquerading as mass test failures (connection-refused `OSError`).
   - *Lesson:* **check DB/container health before trusting a wall of test errors** — a mass failure is often infra, not code.

## Process note (strict-bmad vs. pragmatic)

MasterB is sensitive to Claude bypassing bmad.
